# 七牛 Kodo 联调

这里只说明在本机填写配置。不要把 AK、SK 或恢复密钥贴到聊天、代码或日志里。

## 准备

| 配置 | 填写内容 |
|---|---|
| Endpoint | 空间所在区域的 HTTPS S3 服务域名，例如华东浙江 `https://s3.cn-east-1.qiniucs.com`；其他区域按七牛控制台和官方表核对 |
| Region | 对应 S3 Region ID，例如 `cn-east-1` |
| S3 空间名 | 七牛控制台提供的 S3 空间名，注意不要猜测与其他空间标识完全相同 |
| 对象前缀 | 首次联调建议新建独立 `clipdesk-test-20261111/`；本版绑定后不在线迁移 |
| AK / SK | 具有该私有空间与前缀必要读写/列举权限的凭据；连接测试还需删除测试对象权限 |
| 同步密钥 | 电脑 A 点击首次生成，导出 `.clipdesk-key`；电脑 B 导入同一文件 |

保持空间私有。程序不会修改 ACL，不要求启用公开访问，不会清空已有空间。常规同步不删除远端对象。请求范围只涉及填写的前缀。

## 电脑 A

1. 打开 ClipDesk → 更多 → 设置与同步。
2. 填写上述信息，首次生成同步密钥，导出恢复文件到安全位置。
3. 点击测试七牛连接。它仅对 `<前缀>/_connection-test/` 下一个随机小对象执行 PUT/GET/LIST/DELETE，失败时可能留下该测试对象，但不会删除其他对象。
4. 测试通过，只能记录“七牛真实接口验证通过”。随后开启同步，保存设置。
5. 新建一段专用测试文字、导入一张小图片、创建一项待办和一条备忘，等待已同步。

## 电脑 B

1. 运行相同版本，填写相同 Endpoint、Region、S3 空间名和前缀。
2. 导入 A 的恢复密钥；不要生成另一把密钥。两台显示的密钥指纹应相同。
3. 开启同步，确认文字、原图、来源关联、置顶、待办状态与备忘全部到达。
4. 首次初始化不得替换 B 当前系统剪贴板。

## 两机验收

| 操作 | 预期 |
|---|---|
| A 新复制文字和截图 | B 能查历史并复制原图 |
| A 手动编辑 | B 更新历史，但当前系统剪贴板不被编辑接管 |
| 两机断网修改同一正文，恢复网络 | 两个版本保留，可在详情里选择 |
| A 删除，B 离线持旧版本修改后上线 | 记录保持在回收站；不能静默复活 |
| 主动恢复 | 两边恢复同一 ID |
| 从图创建备忘后删除源剪贴 | 备忘图片仍有效 |
| 上传中退出，重开 | 未确认队列重试，不重复生成内容 |
| 图片暂未下载 | 显示待下载，禁止复制不存在的原图；重试后可用 |
| B 正在编辑未保存草稿，A 修改并同步 | B 草稿不被覆盖；可保存为并发版本。若已存在冲突或 B 本机随后又修改/采用版本，普通保存受阻，草稿可另存新内容 |
| 启用自动接收，双方在线再复制 | B 更新剪贴板但不自动粘贴；本机新复制冲突时优先本机 |
| 断网积压后重连 | 积压进入历史，不接管当前剪贴板 |
| 导出备份，恢复到新数据目录 | 正文、图片、关联、删除/完成状态有效；不携带凭据 |

只有以上实际完成后，才记录“两台真实电脑同步验证通过”。目前结果为未执行。测试前缀建议长期保留作验收；不要直接用存有其他业务对象的根前缀试验。

## 0.2.0 升级注意

所有接收电脑应一起升级。v1 增量包增加受认证的 `liveEligible` 字段；没有该字段的旧事件，以及初始化、恢复和失败后的积压只进入历史。新版接收器才执行这一限制。连续轮询没有观察到的短暂断网不能可靠识别，因此仍需按上表实际验证，不能承诺等同实时推送。

关闭同步会取消正在进行的本轮请求并停止后续同步；本地保存继续。若连接表单有未保存的错误内容，也可以直接使用“关闭云同步”。单条新变更上限 60 MiB，旧超限日志保留并报错，不能跳过游标冒称已经同步。
