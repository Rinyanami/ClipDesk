# ClipDesk 0.2.0：审查与修复

日期：2026-11-11。继续使用同一个 Windows 原生项目，没有重写或改成浏览器演示。

## 这次改了什么

- **保护已保存内容。** 旧草稿不能撤销同机删除；编辑正文保留之后设置的置顶和待办完成状态。版本详情打开后若本机又有修改，必须重新核对再采用。主动恢复的剪贴变为长期保留，避免立即被自动清理再次删除。
- **恢复更可靠。** 备份先校验全部内容及原图，再合并数据库事务；重复恢复不重复入库。损坏原图可用正确备份或同步重新补齐，多个写入者发布同一张图按摘要核实后幂等完成。导出和导入使用一致的体积限制。
- **粘贴更保守。** 一次复制的系统序号、当前浮窗会话、条目和原输入位置绑定；期间剪贴变化就停止自动粘贴。按钮和菜单上的 Enter 使用自身行为。失败仍保留复制结果，提示手动粘贴。
- **更清楚的界面。** 搜索无结果、暂无待办、已完成筛选和回收站分别提示。恢复、缺图和复制反馈显示在当前窗口。设置拆为“本机使用”“数据与恢复”“多电脑同步”，增加可独立关闭云同步的入口。
- **降低重复工作。** 列表使用可回收虚拟容器，合并搜索和刷新，批量查询冲突。缩略图后台降采样并用有界缓存。草稿不再每次按键都同步写数据库，关闭、失焦和退出前补写；未改动就关闭不会生成空草稿。
- **同步补齐异常处理。** 新发现的设备先核验注册，再发布本机内容；损坏设备日志不阻塞其他正常设备，缺图独立重试。S3 分页异常及时停止，保存凭据失败尝试还原，更换凭据后重建客户端。普通编辑不会绕过网络故障退避。
- **隐私与退出。** 跳过 Windows 敏感剪贴标记，按剪贴拥有者识别来源。导入、复制、恢复未完成时阻止中途退出；草稿落地失败时保留编辑窗口。

## 如何理解本次测试

六组智能体参与了源码审查、角色推演、编写回归用例和二次复核；角色推演不是邀请真实用户完成测试。

加固前，原有 49 项检查全部通过，但新增的 7 项针对性检查全部失败。修复后，扩展至 98 项的数据与模拟同步检查全部通过，覆盖 SQLite 事务、损坏备份、并发原图、旧版本、异常分页、误接收旧复制等。最终构建与运行结果见《验收记录》，不能把模拟对象存储等同七牛真实联调。

最后一轮还保护了置顶、完成状态与普通历史清理：未核对的并发版本不会因这些操作被悄悄合并。旧草稿无法覆盖后来保存或明确采用的内容时，可以另存为独立的新记录；另存失败保留草稿，成功才在同一事务中清除旧草稿。

本轮原生编辑器检查使用独立测试数据：快速输入、关闭与重开、写入失败、取消、原文、富文本和缩略图。合成性能对照中，一组连续 40 次文本追加只触发一次草稿写入；这说明减少了重复持久化，不代表所有电脑都达到同一延迟。

## 同步升级说明

协议路径和稳定 ID 不变；v1 传输包增加可选、受 AES-GCM 认证的 `liveEligible` 字段。新版把缺字段的旧包、恢复重发、初始化和失败后的补传作为历史。要得到这一“当前剪贴板”保护，所有接收电脑都应升级到本版本。未升级客户端仍按旧规则判断。

前台本机保存仍先于云端上传。每次真正写入系统剪贴板前再次核对本机变化、配置和事件年龄。轮询没有观察到的短暂断网无法被可靠推断，不能声称等同实时推送。

新变更序列化最多 60 MiB，传输日志密文最多 64 MiB。旧版若已产生超限日志，本版保留内容和游标并报错，需要离线迁移，不能静默跳过。单图最多 64 MiB、6400 万像素；完整备份总计最多 2 GB，元数据最多 128 MB。

## 仍需继续验收

- 真实鼠标双击、中文输入法候选、第三方应用及备忘原光标回填，需要真实前台交互验证。
- 七牛真实接口和两台电脑的断网、重连、冲突流程仍需专用测试前缀与本机配置；不要把 AK/SK 发到聊天中。
- 混合 DPI、多屏拔插、实际登录启动、屏幕阅读器和长期运行尚需真实环境检查。
- 不提供永久清空、远端日志压缩或资源回收。本机和云端容量仍会增长。
- 没有保证“零问题”。版本仍是桌面预览版，继续保留问题与测试记录。

文件系统与 SQLite 不共享一个事务：崩溃或原图发布中途 I/O 失败，可能留下已校验但暂时没有引用的原图。数据库中的正文、草稿、引用和同步队列保持同一事务，避免半恢复记录。
