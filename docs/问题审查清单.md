# ClipDesk 独立审查清单

日期 2026-11-11。审查对象为本轮加固前的 0.1.0 预览版，依据需求、源码和既有验收记录。角色是任务场景推演，真人试用尚未开展。检查使用独立 SQLite 目录、合成文字和两张 2×2 PNG。同步检查使用内存对象存储，覆盖到 `LiveCopy` 事件为止。原生操作、七牛服务端和双设备结果分别见 [验收记录](验收记录.md)。

## 用户任务

| 视角 | 验收任务 | 通过条件 |
| --- | --- | --- |
| 产品经理 | 从剪贴收集到搜索、复制、置顶、转为待办或备忘 | 首页仍可直接查找和复制。转换生成独立快照。更改剪贴正文只影响该剪贴。 |
| 业务验收人员 | 编辑、删除、显式恢复、导出、合并恢复 | 已确认的删除和置顶状态不会被较早打开的编辑窗口撤销。备份可恢复完整正文、原图与关联，损坏备份可报告失败。 |
| 数字技能较少的首次使用者 | 打开软件、找回记录、关闭窗口后再次找到入口 | 使用本机功能无需配置云端。搜索无匹配时能清除条件。能看到记录状态、托盘入口和当前热键。 |
| 集团负责人 | 在个人多台设备间使用并确认隐私和恢复边界 | 能区分本地数据、备份和云端的保护范围。能查到成功或失败证据。当前产品范围是个人多台 Windows 电脑。 |

| 高级用户 | 仅用键盘选取、粘贴、切换到原目标，维护长期历史并处理同步冲突 | Enter 的动作与焦点一致。可确认复制原图或纯文本。长列表中可查到旧记录，冲突详情足以选择所需版本。 |

## 加固前发现

P1 涉及意外粘贴、删除状态被撤销或备份可恢复性。P2 涉及常用流程中断、状态误导或容量增加后的可用性。表中的代码路径记录发现时的行为。检查结果以后续执行记录为准。

| 编号 | 严重性 | 复现路径与影响 | 证据与验收方式 |
| --- | --- | --- | --- |
| 01 | P1 | 先在外部编辑框唤出已有历史的剪贴窗，Tab 聚焦「新建」「更多」或「置顶」，按 Enter。窗口级按键处理可能截获按键并走粘贴。通过目标校验时可能把内容写入外部控件。 | `HistoryWindow.PreviewKeyDown` 在外层处理 Enter。需要 Windows 前台实测按钮激活与列表粘贴。 |
| 02 | P1 | 打开条目编辑器，同机从历史删除记录，再保存原编辑窗口。旧编辑可能使该记录复活。相同路径还可能撤销置顶或待办完成。 | `EditorWindow` 以打开时的条目构造保存内容，`Store.Save` 给新变更分配更高的本机版本。独立检查覆盖删除、草稿保留、显式恢复、置顶和完成。 |
| 03 | P1 | 接收者已经连续在线时，在第三个数据目录恢复刚导出的自动剪贴，随后上传。恢复条目可能触发接收方的在线复制。 | `Backup.Import` 将原 `capture` 动作与时间重新排队，`SyncEngine` 以动作和时间筛选。独立检查先让接收者识别发布设备，验证恢复入历史，再验证新捕获的正向路径。 |
| 04 | P1 | 逐次编辑接近正文上限的条目，积累超过 128 MiB 的 JSON 变更。可能导出成功，合并恢复时才被拒绝。 | `Backup.Import` 有数据与总大小上限，审查时 `Backup.Export` 无对应检查。需要大数据夹具核对导出反馈和可导入性。 |
| 05 | P1 | 先从有效备份恢复原图，再让测试目录的现有原图文件字节损坏，重新恢复同一备份。原图可能继续不可读。 | `AssetStore.Receive` 校验收到的字节后走不覆盖已有文件的写入。独立检查验证可修复原图并继续保持同一附件标识和变更数量。 |
| 06 | P2 | 恢复两张图片的备份，第二张校验失败。第一张可能先被写入正式原图目录，形成孤立文件。 | `Backup.Import` 原来逐张落地。独立检查验证错误时没有新增记录、待上传事件或前部原图。 |
| 07 | P2 | 已同步后仅改凭据，或同时改凭据并输入冲突热键。失败可能留下部分凭据，后台也可能继续使用旧客户端。 | `SettingsWindow.Save` 原先先写凭据再注册热键，`App.SyncLoop` 原缓存键只含连接配置。需要模拟凭据写入失败与替换，原生安全存储另验。 |
| 08 | P2 | 搜索 `école` 时漏掉标题 `ÉCOLE`。无匹配时首页和回收站可能报告历史为空。 | `Store.List` 原查询依赖 SQLite 的 `lower()`，其内建函数只处理 ASCII。独立检查覆盖历史与回收站的 Unicode 搜索。空态文案需在原生窗口验证。 [SQLite 官方说明](https://sqlite.org/lang_corefunc.html#lower) |
| 09 | P2 | 最近 5000 项待办均为已完成时，较旧的未完成项可能从默认视图消失。输入每个查询字符时还可能重建大量卡片并读取原图。 | `CollectionWindow.Refresh` 原先取限量数据后筛完成状态。独立检查以两条任务和一条限额复现查询边界。大列表的原生渲染与内存需独立测量。 |
| 10 | P2 | 打开记录后直接关闭，可能出现空白或完全未修改的草稿。冲突只在图片、到期日或完成状态有差异时，旧详情只能看到标题和正文。 | 检查 `EditorWindow` 的隐藏和关闭路径，以及 `App.Details`。需要以原生窗口验证无改动关闭、保留修改和可比较的冲突详情。 |
| 11 | P2 | 第一次打开设置或失败后再次进入时，本机设置、连接测试和启动同步的操作混在一起。普通列表的更多菜单还可能被浮窗失焦影响。 | `SettingsWindow` 的通用操作原在同一页，`HistoryWindow.ContextMenuOpen` 原先仅检查列表行菜单。需要跟踪实际原生焦点与操作结果。 |

## 回归证据

- 加固前基线在独立临时源码副本运行。Release 编译零警告、零错误，原有 49 项通过。新增的七项均复现异常，覆盖同机删除被旧稿撤销、置顶与完成状态被覆盖、备份捕获触发在线复制事件、损坏原图无法修复、坏备份留下孤立原图、Unicode 漏匹配、已完成任务占用未完成列表限额。待办筛选使用旧窗口的取数与筛选顺序，将限额缩为一条以稳定复现。
- 加固后的独立 Release 快照重新构建并运行，零警告、零错误。该快照共 75 项通过，其中原有 49 项、上述独立回归 7 项、同步专项 19 项。最终交付构建的完整结果另见 [验收记录](验收记录.md)。
- 本地和协议回归入口为 [AdversarialChecks.cs](../tests/ClipDesk.Checks/AdversarialChecks.cs)。七项检查分别报告结果。同步场景只有模拟远端。检查目录由程序生成，实际结果见 `checks.json`。
- 原生验收须覆盖 Tab 和 Enter、单击和双击、目标失效后的手动粘贴、备忘原光标，以及搜索空态与草稿关闭。若进程未获得系统前台，记录受阻步骤和原因。
- 七牛服务端签名、真实凭据管理、两台电脑、长期磁盘容量和长时间运行均单独取证。当前预览版的本机数据库、图片与普通 ZIP 含明文，用户可在多电脑设置中核对同步与自动接收开关。

## 加固中的第二轮复核

下列为审查中间快照时提交的源码问题。前面的 75 项运行不覆盖这些路径，交付时仍须核对对应实现与证据。

| 范围 | 复核发现 |
| --- | --- |
| 采用冲突版本 | 详情打开后若同机又完成、删除或采用了另一版本，随后点旧详情的采用按钮，更大的本机版本序号可能覆盖后来的变化。建议按详情打开时记录的本机版本分量，在提交事务内校验。 |
| 大日志对象 | 单字段字符上限和 JSON 转义相乘后，合法正文与富文本可令日志超过读取端原先的 64 MiB 上限。需核对大日志发布和接收的上限一致。 |
| 设置即时生效 | 在后台准备远端剪贴图片时关闭同步，写回前需再次检查同步开启状态。若关闭时保留了自动接收勾选，只检查该勾选会漏掉变化。 |
| 大图导入 | 如果先解码再验证尺寸，压缩图可在达到像素限制前消耗大量内存。需要验证像素预检和原生内存占用。 |

## 官方资料对应的检查

- Microsoft 的 WPF 预览事件文档说明，外层标记已处理可能阻止子控件处理。键盘回归要同时覆盖聚焦按钮和选中历史行。 [Microsoft Learn](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/events/preview-events)
- CopyQ 将选中条目的粘贴、编辑、复制列为不同键盘动作。Maccy 将输入查询和 Enter 纳入主路径。ClipDesk 的验证可从热键进入，分别测查询、按键切换、复制与粘贴。 [CopyQ 官方文档](https://hluk.github.io/CopyQ/#using-the-app) · [Maccy 官方网站](https://maccy.app/)
- EcoPaste 支持本地备份及加密备份容器。ClipDesk 当前备份入口要清楚提示正文和图片的明文范围，并能在目标数据目录完成合并恢复。 [EcoPaste 官方仓库](https://github.com/EcoPasteHub/EcoPaste)
