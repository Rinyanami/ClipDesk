# ClipDesk：需求与技术决策

日期：2026-11-11。面向个人多台 Windows 电脑；本期不做手机端、团队协作或常驻业务服务器。

## 产品规则

收集或输入 → 历史查找与复用 → 按需置顶、转待办、存备忘 → 多电脑继续使用。首页展示搜索、新建、最近记录及剪贴／置顶／待办／备忘四个可见入口；待办列表、备忘内容仍各自在独立窗口内。此处按用户 2026-11-11 试用反馈覆盖原“待办和备忘藏在更多里”的安排。

| 范围 | 必须遵守的行为 |
|---|---|
| 收录 | 真实系统剪贴板文字、链接、图片；保存原图，缩略展示；磁盘图片可导入、拖入；保留捕获到的 HTML/RTF，明确提供纯文本复制；不运行剪贴内容 |
| 单击与双击 | 单击只复制且不收起、不排序；双击等待第一次复制完成、收起浮窗、验证原输入目标，再尝试粘贴一次；不得自动发送消息或按 Enter 提交 |
| 条目操作 | 内容置顶、编辑、转待办、存备忘、详情、删除；按钮与菜单不冒泡触发复制；上下选择、Enter 粘贴，编辑框 Enter 换行 |
| 编辑 | 新建多行文字/链接；保存只改记录，保存并复制才改系统剪贴板；取消丢弃本次草稿；恢复原文需显式保存；空白拒绝；已有记录保留 ID、排序时间和置顶；手动记录与编辑记录长期保留 |
| 待办 | 标题、说明、图片、到期日期、编辑、完成/恢复未完成、完成筛选、删除/恢复、搜索；日期不称为提醒 |
| 备忘 | 可选标题、多行正文、图片、编辑、搜索、复制、删除/恢复；本机草稿保护 |
| 来源 | 转换创建独立快照，只保留来源 ID；源记录的编辑、清理不影响目标内容或附件；提交幂等 |
| 窗口 | 剪贴、置顶、待办、备忘四窗独立；后三者默认保持显示，各自可设始终最前与未操作时不透明度；再次打开激活原窗口；关闭不是删除；Esc 仅收起剪贴；布局、显示器、热键均为本机设置 |
| 输入目标 | 外部可编辑控件及本应用待办/备忘输入框；浮窗、菜单、普通列表不作为输入目标；目标失效或权限不允许时只保留复制结果 |
| 本地数据 | SQLite 事务提交与同步队列同时落地；断网可用；按天数/数量清理普通历史；软删除；附件引用；完整备份与合并恢复，不含凭据 |
| 同步 | Kodo S3、HTTPS、私有空间、原生签名、Windows 安全凭据；稳定 ID、不可变变更、幂等重试、顺序上传、并发版本保留、删除标记、新设备初始化、草稿隔离 |
| 加密 | 成熟密码库做客户端加密；同步密钥和七牛 AK/SK 分开；新设备通过恢复密钥文件导入；不能把 HTTPS/私有空间当作端到端加密 |
| 远端复制 | 默认只同步历史；可选接收在线新复制；首次初始化、备份恢复、断网积压不接管系统剪贴板；本机新复制优先；不自动粘贴；不回传回环 |
| 桌面基础 | 托盘、明确退出、自启动选项、暂停/恢复记录、排除应用、热键冲突处理、保存/复制/下载/同步状态、重启恢复 |
| 延后 | OCR、真正的系统提醒、手机、更多内容处理 |

## 工作区与 EcoPaste 审查

原工作区是 `Rinyanami/Snapaste` 截图工具，有未提交的 OCR 等改动。本轮只增加 `ClipDesk/`；不修改 Snapaste 代码、README、发布包或其 Git 元数据。

审查官方仓库：<https://github.com/EcoPasteHub/EcoPaste>。

固定提交：`5139d30b0f4c1309356a9b308c05092f1038bc9b`，该提交时间为 2026-08-12 UTC，package 版本 1.1.0。源码审查副本在临时目录 `clipdesk-ecopaste-audit`，不作为第二套产品维护。

机器已有 Node 24.18.0、.NET SDK 10.0.401、.NET Desktop Runtime 10.0.12。未发现 Rust/Cargo 和 Visual C++ 编译工具。Windows Computer Use 在初始化后列窗口时报 `failed to launch codex app-server: program not found`，重试仍失败。

**决定采用单套独立 .NET 10/WPF 实现。** 理由是本期只面向 Windows，已有可工作的原生桌面工具链；EcoPaste 的硬删除、图片单引用与本次多实体、可恢复删除、增量同步的数据契约有实质差异，无法作为简单插件扩展。原版又无法在当前环境编译验证。此决定不表示 EcoPaste 质量不适合日常剪贴管理；只是本工作区本期的工程取舍。没有复制其代码、图标、品牌或其他资源，没有维护一个 EcoPaste 分支和一个独立 ClipDesk。

## 本地设计

- `ClipDesk.Core`：模型、SQLite、附件、备份、加密、S3 适配器、同步协议。
- `ClipDesk.App`：原生 WPF 窗口、WM_CLIPBOARDUPDATE、热键、托盘、凭据管理器、目标验证与一次粘贴。
- `ClipDesk.Checks`：多数据库/模拟对象存储的风险检查、实际 AWS SDK 请求序列化检查。
- SQLite 使用 WAL、synchronous=FULL。内容、版本、附件引用和 outbox 在一个事务中提交；成功反馈在提交之后。
- `entries` 保存当前可见状态；`changes` 保存不可变版本和有效并发版本；`outbox` 保存本设备追加日志序号；`asset_refs` 保存可恢复版本的附件引用；`drafts` 与本机 `meta` 不进入云端。
- 原图文件按 SHA-256 定位，先原子落盘，再保存数据库引用。预览用 WPF 降采样加载，复制使用完整原图。
- 图片限制 64 MB / 6400 万像素，每条最多 20 个附件。首页最多展示最近匹配的 500 条；其他列表查询默认上限 5000 条，备份仍包含完整变更。
- 清理和主动删除进入回收站。为了保留可恢复版本，当前预览版不做永久资源回收或远端压缩；磁盘/云端容量会增长。这是明确的未完成优化，不应写成已经释放空间。
- 内容排序使用创建时间；普通编辑、单击复制、完成待办不会重排原剪贴。

## 同步协议 v1

七牛官方依据（2026-11-11 核查）：

- <https://developer.qiniu.com/kodo/4088/s3-access-domainname>
- <https://developer.qiniu.com/kodo/4093/s3-authentication>
- <https://developer-doc.qiniu.com/products/kodo/development-guidelines/aws-s3-compatible/compatible-s3-api>

只使用 PutObject、GetObject、ListObjectsV2；连接测试额外删除自己的测试对象。使用路径风格、签名 V4，不使用 encoding-type、对象锁、服务端加密、版本化或高级校验协议。真实七牛是否接受这些请求必须继续联调，官方兼容表和模拟检查不能代替实测。

```text
<前缀>/v1/devices/<设备ID>/device.bin
<前缀>/v1/devices/<设备ID>/events/<20位顺序号>.bin
<前缀>/v1/assets/<密钥相关对象标识>.bin
<前缀>/_connection-test/<随机ID>.bin
```

每台设备只写自己的顺序日志。普通变更使用稳定记录 ID、唯一事件 ID、来源设备、版本向量。传输包有独立 writer/sequence，可在恢复备份后重新发布原有事件，接收方仍按事件 ID 幂等。

1. 本地提交先于上传。附件成功上传后才发布引用它的事件；该事件上传确认后才继续下一序号。
2. 即使服务端成功而响应丢失，重试仍使用同一日志路径和同一事件内容。进程重启继续 SQLite outbox。
3. 只列举设备目录，再按每台设备已确认游标 start-after 增量获取。游标必须连续，损坏、认证失败、间断则停止并保留游标。无需扫描图片空间或反复下载已有原图。
4. 普通保存会唤醒同步；无操作轮询逐步退避至 120 秒，失败退避至 300 秒；启用自动接收复制时正常轮询约 15 秒。没有服务端推送。
5. 两个版本互不支配时都保留；UI 提供详情/冲突版本并显式选择。并发删除优先显示已删除；旧设备普通修改不能复活。显式恢复以已见全部版本为基础产生后继版本。
6. 下载状态由资源是否落地判断。缺图时仍展示记录和待下载文案，复制原图被阻止；重试会补齐引用到的缺失图片。
7. 首次同步、进程重启首轮、网络失败后首轮均不自动更新剪贴板。只有短期连续在线轮询中不超过 30 秒的新 copy/capture 事件才候选接收，且本机最近复制优先。时钟偏差或不确定时宁可只入历史。
8. 复制事件与普通保存分开；接收远端剪贴写回通过系统序号抑制捕获，不再发 copy 事件；不注入输入。
9. 启动同步时先解密已有设备注册对象，错误密钥在写入前停止。本版不支持在线更换空间/前缀/密钥；迁移需新数据目录和备份恢复，避免错误混库。

AES-256-GCM 使用 .NET `System.Security.Cryptography.AesGcm`，随机 96 位 nonce、128 位标签；路径/协议参与认证附加数据。原图对象名使用 HMAC-SHA256 隐藏明文摘要。密钥与 AK/SK 分开存 Windows 凭据管理器，恢复文件只包含同步密钥。没有自行设计密码算法。云端仍可见对象路径中的设备 ID、日志序号和文件大小；本机 SQLite/原图不做整库加密。

## 焦点与安全降级

记录 HWND、进程与可编辑控件身份。本应用只接受待办/备忘编辑器的 TextBox；外部使用 UI Automation 核对可编辑控件，粘贴时重新核验前台窗口与控件 runtime ID。只有确认后才调用一次 Ctrl+V，绝不发送 Enter。无法确认可编辑性、窗口失效、前台恢复失败、按键修饰状态未释放或 UIPI 不允许时，只提示手动粘贴。

这是一条保守路径，可能在部分自绘编辑器中只能复制。当前自动化进程未能取得系统前台，故内部备忘原光标回填、跨应用及双击仅实现，尚待真实交互验收。

## 0.3.0 桌面面板调整

- 剪贴首页保留内容主线，置顶、待办、备忘入口直接可见；各窗口只保留一个实例。置顶视图按原记录筛选，不创建副本，取消置顶不会删除历史。
- 保持显示与始终最前分开：前者控制切换应用是否收起，后者控制普通窗口之上的显示层级。无需再加含义重复的“台前”开关。
- 待办、备忘可放在屏幕侧边，分别调整大小、位置和未激活时不透明度。悬停或操作时恢复清晰，保留标题区、窗口按钮、拖动和边缘缩放。关闭窗口只隐藏，完全退出仍走托盘。
- 每个窗口各自设置全局快捷键，保留旧剪贴热键；新增三项默认留空，由用户选择。保存整组热键先验证与注册，失败保留旧组合；开机占用只影响相应入口。
- 设置与布局仅在本机持久化，不参与云同步。旧布局没有新增字段时沿用各窗口默认行为。
- 粘贴在有效主动手势中记录 HWND、输入控件、进程、复制序号，收窗后请求恢复并有限等待；验证通过才粘贴一次。期间发生新的输入、复制或焦点变化则停止，绝不发 Enter。常驻面板鼠标激活前重新捕获目标。
